# Performance Dashboard v0.1.5

Released on **2026-11-06** for **Debian 13 x86_64**. Windows and Linux arm64
packages are outside this release.

The [published release notes](https://github.com/danjboyd/gnustep-performance-dashboard/releases/tag/v0.1.5)
are the final notes supplied unchanged at publication, with SHA-256
`e17e2a36df70cbeb8d825abdbe7ad111e51a2fb0ead51de75433bf02169a916e`.

## Changes

- Signed update payloads, with an Ed25519 public key embedded in the package
  and verified signatures required before final release-feed assembly.
- gnustep-packager v0.1.7 packaging pin.
- `gstrace info` symbol-naming coverage across referenced stacks, including
  Allocations-only traces, plus opt-in report coverage with `--symbol-summary`.
- Fixes for reopened embedded fallback-name status and zero return addresses.
- Sampler fixes prevent allocation-hook re-entry during signal-handler stack
  unwinding and reject overflowing frame-pointer candidates that could crash
  a recorded app when Time Profiler and Allocations ran together.
- Documentation of conservative Leaks limitations; detector behavior is unchanged.

## Updates and limits

The released v0.1.4 client has no update-signing public key. Its first update
uses the legacy update path; the new signature cannot enforce authenticity on
that old client. The key-configured v0.1.5 in-app updater verifies payload
signatures. Independent AppImageUpdate/zsync updates do not use that verification.
Signatures authenticate payload bytes, not feed metadata or the advertised
version. v0.1.5 can accept an older signed payload advertised as a newer
release; rollback protection is planned for v0.1.6.

The exact hosted AppImage passed the real v0.1.4-to-v0.1.5 replacement,
relaunch and About-version check, plus bad-hash/missing-payload recovery
checks. This does not establish signature enforcement by the old v0.1.4
client. Download the final assets and checksums from the published release.

The [qualification and release ledger](../v0.1.5-validation.md#published-v015--2026-11-06)
records the source/tag, seven asset identities, hosted runs, live stable-feed
verification and remaining acceptance limits.
