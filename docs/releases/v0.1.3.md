# Performance Dashboard v0.1.3

Prepared release: **Linux-only, Debian 13 amd64**. The tag and
publication are pending separate approval. v0.1.0 is the previous published
release; v0.1.1 and v0.1.2 were unpublished internal milestones. v0.1.3
includes their changes. Windows packages are deferred.

## New since v0.1.0

- **Allocation generations:** name checkpoints and inspect allocations born
  in one generation that survive at a later checkpoint. View categories,
  surviving allocations and allocation stacks. Generation sidecars travel
  with the recording through Save As and reopening.
- **Compare recordings:** choose independent time ranges or complete signpost
  intervals. Compare target-process CPU self time and call paths, allocations,
  leak snapshots, signpost durations, and file/network bytes. Missing recording
  types are rejected and recording-quality warnings remain visible. Values
  are absolute, not normalized by workload.
- **Richer hang evidence:** inspect estimated main-thread CPU and overlapping
  I/O, then open the hang's wall-sampled call tree. The evidence does not
  establish scheduler states, lock ownership or causality.
- **Source navigation:** open recorded stack frames in a numbered source view,
  locate moved source directories and open files in an editor. Matching
  executables/debug information and host addr2line remain prerequisites.
- **Investigation-window layout:** improved resizing and clipping behavior
  for generation and comparison windows, using standard theme controls.
- **Profile the viewer:** opening an existing trace emits a real OpenTrace
  signpost interval through the optional public API library.

The stream remains format v1. Existing recording types, CLI exports,
conservative leak diagnostics, helper attachment and trace saving remain
available. Linux packaging pins gnustep-cli-new v0.1.2 and gnustep-packager
v0.1.4; dependency versions are distinct from the app's v0.1.3 version.

## Download and run

Planned assets include `PerformanceDashboard-0.1.3-x86_64.AppImage`, its
`.zsync`, `SHA256SUMS`, provenance, stable update-feed JSON and
`PerformanceDashboard-0.1.3-sources.tar.gz`. Verify downloaded files against
the exact release checksums before running them.

```sh
sudo apt install libxft2 libxt6t64 libcairo2 libglib2.0-0t64 libdbus-1-3 libunwind8 binutils fonts-dejavu-core
chmod +x PerformanceDashboard-0.1.3-x86_64.AppImage
./PerformanceDashboard-0.1.3-x86_64.AppImage
```

Use X11 or XWayland. Without FUSE, set `APPIMAGE_EXTRACT_AND_RUN=1` or extract
with `--appimage-extract`. The CLI is
`squashfs-root/usr/runtime/bin/gstrace`. Targets use their own runtime;
the package supplies the viewer's GNUstep environment. Launch recording needs
no administrator privileges; attachment uses the optional profiling helper.

## Known limitations

- **Exec-wrapper launch:** a shell script that execs the target can open the
  app while leaving an empty, unclean recording labelled as the shell. Select
  the target's native executable directly, for example `MyApp.app/MyApp`.
  The fix stays in v0.1.4 and is not present in these v0.1.3 bytes.
- **Large traces:** opening a roughly 325 MiB allocation-rich trace can block
  the main loop for about 2.7 seconds and reach approximately 1 GiB resident
  memory in the measured workload. Background loading and memory reductions
  are v0.1.4 work. These observations are not a universal size/performance bound.
- **Unsigned package and update feed:** updates use HTTPS and SHA-256 integrity
  checks, without an independent signing trust root. A matching digest does
  not provide an independent publisher signature. Stable-feed deployment is
  a separate release step.
- Leak results are conservative candidates. Unavailable or denied scans are
  reported explicitly, not interpreted as leak freedom. Allocations and leak
  scans change target timing and memory use.
- Host libunwind is needed for optimized-stack unwinding and host binutils
  for source lines. GCC/legacy Objective-C CPU profiling is covered at -O0/-O2;
  class tagging and Zombies with that runtime remain unverified.
- Native Windows packages and supported-client acceptance are deferred.
  Other distributions, musl/static targets, 32-bit targets, native PDB source
  lines, scheduler/lock tracing and hardware counters are outside this release.
