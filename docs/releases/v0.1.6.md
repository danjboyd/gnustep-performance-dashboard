# Performance Dashboard v0.1.6 (draft)

Linux amd64; release qualification targets Debian 13.

## Recording
- Add --max-size and --min-free storage guards for launched Linux recordings. The recording dialog shows the free-space floor, and traces retain the reason a recording stopped and whether capture completed.
- The --max-size limit requests a graceful recording stop. Buffered data and target shutdown can take the recording beyond that threshold; it is not a hard disk quota or reservation.
- Propagate recording write/finalization failures and identify incomplete or unverified recordings, preserving available trace data for inspection.
- gstrace preserves a launched program's nonzero exit or signal result. A recorder-requested orderly stop succeeds; forced SIGKILL escalation returns 137, and an unavailable exit status returns failure.
- Default file names in the GUI and CLI use a readable timestamp and a unique identifier, preventing same-second recordings from choosing the same path. Explicitly chosen existing paths are still refused.
- Recorded applications keep their caller's runtime configuration and search paths when launched from the AppImage, extracted AppRun or bundled CLI, including empty and unset GNUstep configuration values.

## Updates and packaging
- Linux: update downloads are verified against the system's trusted certificate store.
- Bind signed update payloads to the advertised package, version, channel and platform, with refusal of relabelled or replayed updates and missing required version signatures. Compatibility with the v0.1.5 update path is retained.
- Use pinned gnustep-packager v0.1.10 updater sources and the GNUstep CLI v0.1.5 Linux SDK, with stronger release-input and assembly checks.

## Known limitations

- Adwaita rounded window corners and shadows aren't drawn: the bundled GNUstep gui/back lack the CSD patches; planned for v0.1.7.
- During local Linux qualification, GUI-launched recordings often could not read the target's exit status (ECHILD). A complete trace remains available and is shown normally; the trace window displays “Exit status unavailable” without a modal alert, and its tooltip includes the saved wait error. The child-status ownership problem remains unresolved. CLI exit reporting is unchanged: unavailable status returns failure; none of the retained CLI qualification records had unavailable status. CaptureStatus describes recorded-data completeness independently of target exit status.
- Size limits with followed child processes, and explicit storage thresholds when attaching to a process, remain unqualified and are refused. Disk-space and size guards request a stop; they do not reserve storage.
- This release scope is Linux amd64. Windows and arm64 release qualification remain separate.
