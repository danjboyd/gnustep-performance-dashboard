# Performance Dashboard v0.1.7 (draft)

Linux amd64 candidate; qualification targets Debian 13. This is a local,
unpublished preparation. A new custom SDK, review AppImage and compositor/GUI
checks are still required before release claims can be made.

## Window decorations and packaging

- Prepare Adwaita rounded window corners and shadows through an unofficial,
  application-owned GNUstep SDK carrying PD backports of the public v7 gui/back
  CSD patches. The source patches apply strictly to the retained PD component
  pins; visible corner/shadow behavior is not yet qualified on this candidate.
- Pin the custom SDK's seven components and15 patch files, including the eight
  Base TLS carry patches. This is a custom build, not an official managed SDK.
- Require the exact custom backend and a same-SDK rebuilt theme when staging.
  Refuse fallback to the older backend without CSD support. Missing CSD backend
  keys or the GUI backend-defaults export stop custom packaging.
- Record the custom lock, SDK provenance, theme receipt and patch hashes in a
  separate unsigned-review provenance path. Selected ELF build-ID comparisons
  and final hashes supplement that identity record; they do not qualify runtime
  behavior or prove every transformed payload byte.

## Recording

- GUI-launched targets use a registered Foundation task as their exit-status
  owner. A small libc-only exec helper preserves intended stdio, caller
  environment, working directory and the agent's writer-status channel before
  becoming the target in the same PID. This addresses the competing child-reaper
  mechanism behind retained GUI ECHILD results; packaged GUI validation is pending.
- GUI targets run in an independent session/process group. Foundation reports
  normal exit versus signal, but not the kernel core-dump flag. Saved metadata
  and the status tooltip identify this limit. The CLI retains its direct launcher,
  terminal/session behavior and original wait status, including the core flag.
- Capture completion remains separate from process exit status. Agent receipts,
  finalization markers and a valid END record are still required; an unavailable
  exit result is never treated as a successful target exit.

## Carried behavior and limits

- Retain v0.1.6's --max-size/--min-free Linux launch guards and write/finalization
  failure reporting. Thresholds request a graceful stop; they are not storage
  reservations or hard disk quotas, and buffered output can exceed a threshold.
- Retain unique suggested trace paths, explicit existing-path refusal, and caller
  runtime configuration handling, including set, empty and unset GNUstep values.
- Retain strict Linux certificate verification and update payload binding from
  the v0.1.6 preparation. This draft does not publish a feed or apply an update.
- Size limits with followed children and explicit storage thresholds when
  attaching remain unqualified and refused. Attaching does not reap the target.
- Windows and arm64 release qualification remain separate. No Linux SDK, visual
  or performance result here qualifies those platforms. No speed or RSS
  improvement is claimed from these correctness checks.

## Validation status

Source/backport application and native headless correctness checks are recorded
in the candidate's validation packet. They do not establish that the new custom
SDK builds or that rounded corners, shadows, theme interaction and GUI recording
work in the final package. The next scheduled windows cover those exact inputs
and loaded binaries, with explicit cleanup and a lead START gate.

Product 0.1.7 is independent of framework library VERSION 0.1.5; ABI/SONAME 0 is unchanged; don't hardcode private fully-versioned library filenames.
