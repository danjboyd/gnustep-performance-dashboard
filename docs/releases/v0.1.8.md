# Performance Dashboard v0.1.8 (draft)

Local Linux amd64 preparation targeting Debian 13. Publication and signing are
separate approval steps; these notes do not qualify Windows runtime behavior.

## Recording and symbols

- Start a launch or Attach recording from a Linux welcome window, with recent
  targets, template availability reasons and process eligibility shown before
  recording. Existing CLI-style GUI launch arguments remain supported.
- Isolate GNUstep application defaults from the recorded program’s arguments.
- Finish writing recording metadata before exposing recording completion to
  polling clients, including the GUI.
- Capture loaded GNU ELF build IDs outside signal handlers. Refuse mismatched
  local images or separate debug files rather than attributing their symbols
  to another build. Legacy traces remain readable; local debug roots supply
  symbols without network lookup. Ambiguous mapping lifetimes retain fallback
  labels. See [the format contract](../trace-format.md).
- The helper still has a documented identity race between the controller’s
  process check and the kernel operation; no new atomic attach protocol is
  claimed.

## Packaging

- Pin the separate GNUstep Trellis libraries for the welcome window and include
  their public source and license information in the source inventory.
- Pin gnustep-packager v0.1.12. Retain its default warning policy for loader
  search-path diagnostics; local AppImage validation records the findings.
- Keep development app RUNPATH and source prefixes independent of checkout
  location; staging replaces the development paths with payload-relative paths.
- Preserve the published v0.1.7 SDK lock and review record; v0.1.8 application
  review bindings are separate.

Product identity is 0.1.8 in the package, app, CLI, helper and recorder metadata.
Framework library VERSION remains 0.1.5 with ABI/SONAME 0, as for v0.1.7; product
version and library ABI are separate. No fully versioned library path is part
of the consumer contract.

## Qualification

Affected unit and integration checks accompany the local review packet. Final
full-suite, clean AppImage and hosted release qualification must be reported
from their actual runs; no publication is authorized by these draft notes.
