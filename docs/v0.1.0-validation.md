## Package acceptance and final regression

- Debian evidence: `Tests/out/debian-final/`; helper: `Tests/out/helper-vm/`
  and disposable-container logs. VM tests invoke the helper with the polkit
  caller environment; an interactive authentication dialog was not automated.
- Updater UI: `Tests/out/update/`; failure/recovery: `Tests/out/update-failures/`.
  Packages and feeds are unsigned; update integrity trusts HTTPS and SHA-256.
- GUI save/reopen: `Tests/out/save-accepted-hashes.json` and
  `Tests/out/save-reopened.png`, visually inspected.
- Real-app packaged recording exposed a DISPLAY regression: environment cleanup
  removed empty colon-separated components, changing `:4` to `4`. The fix
  preserves separators while removing bundled paths. Unit coverage checks
  DISPLAY, URL and path-list values; the end-to-end AppKit fixture exercises
  cleanup before connecting to its private X server. Earlier C-target package
  smoke results did not cover this failure.
- Building the application still requires Clang/libobjc2. Legacy-runtime CPU
  results do not establish Objective-C class tagging or Zombies compatibility.

The release source archive includes application and bundled dependency sources,
an inventory and checksums. The final acceptance receipt is published with the
binary so its identity does not depend on a self-referential source commit.

The prerelease feed also offers v0.1.0 so local RC users can upgrade. RCs
correctly reject a feed labelled stable; the RC-to-final acceptance uses the
prerelease channel, then the installed final build uses the stable channel.

The corresponding-source archive checksums were all verified, including the
application source and licensing files against the release checkout.
