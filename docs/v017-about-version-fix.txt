Proposed behavior
Every successful app build stamps its built Info plist with the effective
GP_PACKAGE_VERSION from the packager, or package.version for plain make.
CFBundleShortVersionString/CFBundleVersion/ApplicationRelease/FullVersionID
must all match. No tracked source plist is rewritten. Incremental builds
restamp even when the executable need not relink. About reads main-bundle info,
with ApplicationRelease fallback for older bundle conventions, and an honest
unknown if metadata is absent. No numeric About literal remains.
Stage refuses a stale/mismatched bundle before mutating the stage root. Final
AppImage extraction checks again against the command's effective package
version. This covers -PackageVersion review versions as well as plain builds.
The effective environment contract was inspected in pinned packager a5c384b1,
Get-GpPipelineCommandEnvironment; stale caller GP_PACKAGE_VERSION is replaced
by its effective manifest before invoking build/stage commands.

The new source-only tests exercise GNUstep ASCII/XML/binary metadata, preserved
nonversion entries, incremental restamping, invalid values, duplicate refusal,
and an actual checker subprocess that fails a deliberately stale plist and
passes only after correct stamping. Source-wiring checks reject a restored
numeric About literal. No compiler, app, GUI or package was run for this fix.
Compiled/About visual qualification requires the lead's new laptop slot.

The stage checksum in the proposed combined input manifest and its unrendered
receipt template is refreshed because the version check changes that reviewed
source file. The SDK lock/16SDK patches, CSD patch bytes/order and the original
frozen manifest remain untouched. This is a new proposed review identity, not
a claim that the changed source still has the old reviewed hash.
