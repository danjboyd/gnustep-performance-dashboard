## Features

- **Allocation generations:** Analysis → Allocation Generations. Name an
  increasing checkpoint at the inspection-range end, enter an explicit time,
  or use Mark Now during a recording. Categories show allocations born in
  that generation and surviving at an independent later checkpoint. Inspect
  surviving allocations or their grouped allocation stacks. Marks persist in
  `generations-PID.plist` inside the trace; Save As carries them along.
- **Compare recordings:** Analysis → Compare Recording. Choose a baseline,
  then independent ranges in seconds, or complete signpost intervals in each
  recording. Compare target-process CPU self time, inclusive CPU call paths,
  allocated/leaked bytes, complete signpost average duration and file/network
  bytes. Values are absolute, not workload-normalized. Only changed rows are
  shown. Missing instruments are rejected; recording-quality warnings remain
  visible. Leak comparisons use snapshots at/before the selected ends.
- **Hang evidence:** the Hangs list shows estimated main-thread CPU and
  overlapping main-thread I/O. Extended Detail explains their limits and
  lists overlapping operations. Double-click a hang for its wall-sampled call
  tree. This does not establish scheduler states, lock ownership or causality.
- **Source navigation:** double-click an Extended Detail stack frame to open
  a numbered source view at its recorded line. Locate Source remembers a
  directory mapping; Open in Editor uses the platform's default association.
  Matching binaries/debug information and addr2line are prerequisites. Source
  contents are local and must match the recorded build; native PDB lookup and
  source-line cost attribution are not implemented. Windows PATH lookup is
  case-insensitive. Full debug-source paths are retained.

The stream remains format v1; all analysis uses existing records. New view
metadata is a sidecar ignored by old readers. Flame graphs, scheduler/lock
tracing, reference graphs, VM-region accounting and hardware counters remain
outside this release's committed scope.

## Validation and ownership

agent owns native runtime/package qualification and validates these features
under WinUITheme. Changes to shared files are coordinated before editing.

Automated coverage includes generation boundary/free/address-reuse semantics,
range and call-path comparison, partial/open signpost exclusion, latest leak
snapshot selection, main-thread-only hang evidence including I/O crossing the
range boundary, and source mappings including Windows drive letters.
`Tests/investigation-gui-checks.sh` exercises the actual controllers with
synthetic traces and captures private-Xvfb screenshots under Adwaita and
Sombre. `scripts/check-linux-release.sh` includes that gate.

Both platforms must build/test the same final source revision and qualify
packages with matching version identifiers before simultaneous publication.
At candidate freeze, align app/CLI/framework/package version identifiers with
the chosen v0.1.2 candidate; this implementation does not bump release labels.
Native Windows validation must cover the Analysis menus, persistence after
reopening a trace, signpost range selection, hang drill-down, actual optimized
DWARF lookup with `Path` casing, missing-source remapping, resize behavior and
source editor navigation. CLI regressions and both directions of native
trace exchange must continue passing.

Windows clean-client installation and update acceptance remain blocked: the
Windows agent reports Dan confirmed no client is available. Server 2022
developer-host tests, even with sanitized PATH, are not that evidence. The
