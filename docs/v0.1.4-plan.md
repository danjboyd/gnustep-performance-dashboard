## Candidate v0.1.5 diagnostics, observed while dogfooding

These are proposals for prioritization, not assigned implementation work.

1. **Weighted hang trees in the CLI/exporter.** `gstrace report hangs` currently
   prints one representative stack. The framework and GUI already support
   weighted wall trees, but this investigation needed a separate diagnostic
   tool to export them. Expose the existing analysis with interval and sample
   weights; preserve the distinction between wall samples and scheduler/lock
   causality.
2. **Actual runtime provenance.** Show loaded GNUstep/Objective-C library paths,
   build IDs and available component/package identities alongside target
   identity. It should make host-versus-bundled runtime comparisons clear;
   an app's source hash alone was insufficient here. Preserve optional debug
   archive/build-ID mappings for stripped libraries.
3. **Named workload-phase bookmarks.** Record and export external phase labels
   such as Open, Edit, Save and Split, then align comparisons by those labels.
   Existing signposts cover instrumented targets; an external user workflow
   currently needs a separate timestamp receipt.
4. **Cancellation during large-trace parsing.** Closing a load window currently
   discards the eventual model, while its worker continues allocating and
   parsing. A cooperative cancellation path would limit avoidable work during
   repeated real-app investigations; it must preserve clean publication and
   the existing analysis-equivalence checks.

The [layout/runtime finding](upstream-review/markdownviewer-layout-runtime.md)
separates the host's known unguarded glyph check from the published v0.2.5
package, where that method is already a one-byte return. The independent
published workflow still shows multi-second rendering/Split and syntax
highlighting stalls. The finding remains prepared-only; no duplicate upstream
report or source submission was made.
