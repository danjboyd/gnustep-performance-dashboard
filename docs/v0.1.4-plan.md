## Dashboard fixes and remaining investigations

The assigned local implementation is complete at source `5e3d295`.
[Validation and limits](v0.1.4-validation.md) record the exact package,
measurements and checks. This is development evidence, not release acceptance.

1. Large-trace responsiveness: existing opens now parse/resolve records,
   prepare analyses, embedded symbols and the initial CPU tree on a worker.
   A standard progress bar is visible until the completed model is published
   on the main thread. Three warm-cache opens of the original 340,831,476-byte
   trace detected no main-loop hang of 250 ms or longer; before had
   2.720–2.780 s hangs. Peak RSS fell about 4% to 947,576–948,076 KiB, still
   approximately 926 MiB. Further work should bound event/analysis storage,
   improve cancellation during parsing, and investigate live-recording update
   cost. Keep source navigation, analysis equivalence and main-thread-only UI.
2. Shell wrappers: the agent keeps injection settings across same-PID exec,
   with default child exclusion retained. Atomic stream replacement and reader
   epoch detection keep final-target data usable during live reload. Minimal,
   delayed and real ScreenshotTool wrapper checks passed. Pre-exec events are
   discarded; non-exec child processes still need explicit following. Native
   Windows behavior is not established by these Linux changes.
3. Recording overhead: [profiling guidance](profiling.md) now explains the
   recording types' costs and the combined/CPU-only distinction. Preserve
   externally measured unrecorded controls and repetitions before making a
   slowdown or speedup claim. UI responsiveness and signpost duration remain
   separate measurements.
