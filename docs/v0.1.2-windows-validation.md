## Native fixes and repeatable checks

The baseline picker previously permitted both files and directories. The
pinned WinUITheme only enables its native folder picker when files are
disabled, so the previous dialog navigated into a `.gstrace` bundle instead
of selecting it. The controller now requests directories only, matching
the reader's bundle input. A disposable copy of this exact setting was
verified with the native Select Folder button before changing shared code.

The earlier physical hang-row attempts were inconclusive: the isolated probe
waited with `NSRunLoop` without dispatching AppKit input events. The common
controller test now sends an actual outline double-click event and queues
its mouse-up. It verifies both entry into Call Tree and the selected hang's
exact inspection-range bounds. This is an AppKit-event regression test,
not a claim of physical desktop interaction. No product hang-handler change
was needed.

Run the native gate after building the app/framework, with the verified
toolchain and a runtime containing WinUITheme:

```powershell
powershell -NoProfile -File Tests/investigation-windows-checks.ps1 `
  -ToolchainRoot dist/verified-toolchain `
  -RuntimeRoot 'path/to/portable/runtime'
```

The runner compiles the common controller probe, requires its successful
exit and final `All 14 investigation GUI checks passed.` line, and captures
only its own windows. It writes `result.json`, logs and screenshots under
`Tests/out/investigations-windows`. It never sends physical input or captures
the desktop. All 14 assertions passed during development; the hang/source
screenshots were inspected. An unattended desktop can deny foreground and
cursor access, so native file-picker acceptance is recorded separately.

The shared Linux test has two additional functional assertions. Its completed
Adwaita/Sombre rerun is recorded below. Candidate package evidence must name
its exact source revision and hashes; these feature checks do not qualify
a different package or waive the clean-client gate.
