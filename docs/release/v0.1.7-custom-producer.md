# Custom unsigned producer integration — review item (c)

The automatic Release workflow reads the committed producer selection. For
custom-csd it calls csd-review.yml with explicit mode=production and the
selected version. Numeric unsigned production is accepted only when that
version equals package.version and the selected producer is custom-csd.
Manual review mode retains the -review suffix requirement. Validation repeats
before acquisition, in both host/container drivers, source collection with CI
evidence, and the final inventory CLI. No secret is passed; real signing is
absent from these workflows. Neither mode publishes a tag, release or feed.

`collect-release-sources.py` is the sole acquisition implementation. The old
collect-csd-sources.py is now a compatibility CLI delegating to its explicit
custom mode with CI evidence; it contains no network/source-fetch logic.
`verify-csd-sources.py` is the independent read-back verifier, not a second
collector. The common collector includes all14 source identities (seven SDK
components, Adwaita, packager, builder, robin-map, appimagetool, AppImage runtime
and tools-xctest), exact16 patches, app patch/applied-source tie, Debian source
versions, original SDK provenance and container/cache/theme/fallback receipts.
The verifier still checks archive bytes, CMake evidence, source commit PAX
comment, public patch index, paths, Debian descriptors and checksum coverage.
Final aggregate receipt checks source metadata against the same binary inputs.
Unsigned numeric outputs retain exact application commit in provenance,
corresponding sources and canonical aggregate receipt. Signing must consume
that future reviewed head/output, never relabel the older local artifact.

The owned builder checkout disables text conversion through .git/info/attributes,
then checks out the committed index and refreshes it before identity checks.
The pinned repository contains a mixed-CRLF patch marked text/eol=lf; leaving
that conversion enabled makes exact blob bytes appear dirty. This scoped
checkout preparation preserves immutable source bytes and does not loosen
builder head, cleanliness or inspected-file digest gates. A synthetic Git
fixture covers the raw-byte/index behavior; no retained checkout was changed.

All current validation is offline/synthetic. No Docker build, producer run,
network fetch, cache save, source acquisition or real signing ran here. Hosted
fresh/cache production remains unrun and needs exact-head approval. Ordinary
CI at the older b6624b9 review ref passed separately; it is not evidence that
this producer has run. The item(b) fail-closed placeholder is replaced only
by this explicit unsigned custom call. Signing adapter item(d) remains separate.

Use a disposable Debian13 VM, with a new private passwd home, runtime/D-Bus
scope and owned Xvfb display. No developer-home or laptop-specific paths are
required: derive paths from the checked-out repository and VM evidence root.
The project cannot reserve laptop quiet windows or pause AIManager agents.
The lead arranges a VM through Dan's ask, or a verified idle period separately.
Do not dispatch/build/apply an update merely because this plan exists.

After an approved producer run, record its exact run/head/artifact IDs, download
only its frozen unsigned outputs, verify canonical aggregate/source receipts
and every asset hash, then extract that exact AppImage. Repeat bundle/CLI/
helper/RecorderVersion0.1.7 and FormatVersion1 checks, unit/headless and final
closure gates as applicable. Visually inspect About under Adwaita and Sombre.
Compositor-dependent acceptance needs a separately approved private compositor
session on the VM (move/resize/maximize/restore/close/focus/menu and corners),
with image/theme/maps identity ties; Xvfb without a compositor cannot prove it.
Keep failed attempts, preserve exact bytes, stop/reap only owned processes and
report empty owned-process/display evidence before releasing the VM. No
signing, public release, feed advancement or installed-app replacement is part
of this unsigned qualification plan.
