## Ordered boundaries

1. `sign-custom-candidate.yml` has workflow_dispatch only, read-only
   contents/actions permissions and no reusable/push/tag trigger. Inputs are
   a named producer run, full commit and selected existing environment. The
   preflight job has no real signing secret. It requires a successful run in
   this repository at that exact commit, from release.yml or csd-review.yml,
   and one unexpired custom-csd-unsigned-production artifact with an API digest.
   PRs, forks, ordinary CI/review artifacts, incomplete artifact listings and
   mismatched versions/commits are refused.
2. After environment approval, repeat those read-only gates, download the
   exact artifact ID and verify its ZIP digest before bounded flat-file
   extraction. Reject paths, links, duplicates and stale outputs. This API
   digest check is separate from the producer's per-file/canonical receipt.
3. The adapter independently verifies the unsigned aggregate/source metadata
   and exact source commit, and all five promotion input hashes. Only then
   does it locate a bounded SquashFS v4 payload and use unsquashfs into a fresh
   path. The unsigned AppImage is never executed in the signing job.
   Check unchanged image bytes, selected payload/provenance ties and exactly
   the extracted updater config's package ID, version/backend/platform and
   public anchor against the expected public variable/source manifest.
4. Preserve original producer provenance bytes as separate signing evidence.
   Add updatesPackageIdentifier and updatesPublicEDKey to a copy, bound through
   signingAdapter to original provenance hash, aggregate receipt hash, image
   hash, extracted config hash and producer run/artifact request. Record the
   new provenance hash in provenance-adapter.json. Do not weaken assembly or
   rewrite the input artifact. Evidence is not an extra public release asset.
5. Run disposable-key refusal tests before the only secret-bearing step.
   That step disables tracing and invokes sign-update-feed then --verify on
   the exact copied feed/payload. Only the signer process consumes the existing
   scoped private secret; the agent/adapter never retrieves or inspects it.
   No key generation, rotation or settings change occurs in the product path.
6. A later step has only the public variable and invokes assemble-release with
   --require-signatures, exact version/commit and AppImage backend. Only five
   verified inputs enter assembly; it adds SHA256SUMS and assembly.json for
   seven public candidate files. Upload the candidate and separate original/
   adapter evidence as Actions artifacts. No GitHub release/tag/feed push or
   installation is performed. Hosted signatures and assembly remain unrun.

All API downloads and real secret use happen only after a future exact scoped
Dan authorization. Inputs reach shell code through env, never run-string
interpolation. Request/download paths stay under ignored out/ so receipt
verification can require a clean checkout. Output/evidence paths are fresh.
The producer workflows never invoke this manual workflow automatically.

present/unlisted runtime passes. The focused negative test removes the runtime
declaration while leaving its bytes, then removes its archive while retaining
the declaration; both fail. Total remains14 declared sources.
